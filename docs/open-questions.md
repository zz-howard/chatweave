# 待定问题（草案）

按影响从大到小排列。每条写明当前倾向，确认后转入 [decisions.md](decisions.md)。

已关闭：流的粒度（每条消息一条流，D20）、事件日志保留期（`message.end` 后 10 分钟，D21）、事件日志的默认存放（进程内缓冲，重启后给快照，持久日志可选，D42）、澄清问题的自由文本回答（作为普通消息发送，D22）。

1. **客户端是否需要完整 JSON Schema 校验？**
   当前倾向：不需要，客户端用类型化解析 + 限制检查，Schema 一致性靠夹具保证（见 mvp-plan R5）。如果将来接入不受信任的第三方服务端，再考虑。

2. **`fallbackText` 由谁生成？**
   当前倾向：内置类型由 `chatweave-server` 提供默认生成器（按 locale 的简单模板），宿主可覆盖；自定义类型由宿主生成。待定：默认模板的语言覆盖（中文 / 英文先行）。

3. **文本中嵌入结构化块（例如代码围栏里的 JSON）是否支持？**
   当前倾向：v1 不支持。结构化内容只能通过受控工具提交。如果某类外部 Agent 只能输出文本又需要组件，再设计带转义规则与增量解析的边界协议。

4. **块级可见性（仅群聊场景）。** 一对一会话只有一位用户，不存在这个问题。在群聊里，某些块的数据可能只有部分成员有权看到。库是否需要块级的“受众”标记，还是完全由宿主在同步 / 流下发时过滤？
   当前倾向：库不引入权限概念；宿主在下发（流、同步）前过滤或替换为降级文本，并可以按接收者告诉渲染器某个交互块对当前查看者只读（只影响展示，真正的检查仍在服务端）。需要首个宿主的实际需求来确认。

5. **数字格式化与本地化。** `valueFormat` 只给语义提示；日期、货币、百分比的本地化依赖宿主传入的 locale。是否需要允许生产方给出“权威显示字符串”（例如特殊单位、分数）？
   当前倾向：不允许，避免表现层回流到协议；确有需要时 `value` 用字符串。

6. **图片与附件。** v1 不加载任何图片。将来如果需要（例如照片、凭证缩略图），倾向只允许“宿主资源引用”（由宿主组件按 ID 从本地或已鉴权接口加载），永不允许远程 URL。

7. **A2UI 适配器的时机。** 触发重新评估的条件：A2UI v1.0 定稿且 Flutter 渲染器发布稳定版；或需要模型自由组合界面；或需要接入只会输出 A2UI 的外部 Agent。

8. **协议包的发布方式。** Rust crate 发布到 crates.io、Dart 包发布到 pub.dev 的时机与命名是否可用（`chatweave*` 名称是否已被占用需在建仓时核实）；1.0 之前是否只用 git 依赖。

9. **示例 App 的 golden 环境。** golden 只能在固定工具链里生成；库仓库的 CI 用哪个固定环境（容器镜像）生成与校验，是否与宿主共用。

10. **作废某一步并重试。** 多步生成中，上游模型某一步失败后重试，是否需要一个事件把“自上一步边界以来已发出的块”作废（类似 Vercel AI SDK 的 `reset-step`）？
    当前倾向：0.1 不做。已发出的块不撤回，失败就以 `interrupted` 结束或把失败的组件块降级为兜底文字，宿主可以发起新一轮。真要做时需要回答：作废的块在折叠和持久化里怎么表示、已续传到一半的客户端怎么回退、界面怎样避免跳动。
