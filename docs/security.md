# 安全（草案）

> **状态：草案。** 本文列出 ChatWeave 面对的威胁、库负责的控制措施，以及必须由宿主承担的部分。

## 1. 威胁模型

| 来源 | 可能的问题 |
|---|---|
| 模型输出（包括被提示词注入操纵的模型） | 伪造组件、塞进 HTML / 脚本、超大数据拖垮客户端、诱导执行危险操作、编造数字 |
| 外部 Agent / 适配器 | 输出不可信文本；适配器“猜”出错误的业务事实 |
| 被篡改或恶意的客户端 | 伪造动作请求、重放请求、提交块里没有的选项、越权访问别人的消息流 |
| 网络 | 断线、重复投递、代理缓存、续传时拿到别人的事件 |
| 宿主自身疏漏 | 动作处理器忘记权限检查、事件日志保留过久 |

## 2. 十条基本要求与落实

| # | 要求 | 落实 |
|---|---|---|
| 1 | 所有结构化内容经 Schema 校验 | 服务端在发出 `block.data` 和持久化前用 `chatweave-protocol::validate()`（JSON Schema + 限制）校验；自定义类型必须注册 Schema，未注册的自定义类型拒绝发出。客户端再做类型化解析与限制检查 |
| 2 | 组件类型白名单 | 客户端只渲染注册表里的类型；其余一律降级为文本。服务端只能发出内置类型和已注册的自定义类型 |
| 3 | 不执行 Agent 输出的任意 JavaScript | 协议里没有任何可执行内容的字段；Flutter 原生渲染，不用 WebView |
| 4 | 不允许绕过设计系统的任意 HTML / CSS | 块里没有样式字段（Schema 的 `additionalProperties: false` 拒收 `color` 之类的字段）；Markdown 中的 HTML 按纯文本显示 |
| 5 | Markdown 安全渲染 | 解析层面的受限子集（[rendering.md 第 3 节](rendering.md#3-markdown-安全子集)）：不加载图片、不渲染 HTML、链接协议白名单 + 打开前确认 |
| 6 | 数据引用验证作用域与权限 | v1 没有数据引用；自定义块推荐只放 ID 引用，**由宿主组件从宿主本地已授权的数据中读取**，读不到就显示“不可用”。Phase 2 的 `dataRef` 只能指向同一消息内的块数据，由服务端校验 |
| 7 | UI 动作 ≠ 工具执行授权 | 动作只能引用服务端持久化的块中声明的 ActionSpec；dispatcher 依次做声明匹配、状态、按块校验 payload、破坏性确认、宿主 `authorize`、幂等（权限检查在幂等回放之前，失去权限的人拿不到旧结果），再执行（[protocol.md 5.2](protocol.md#52-服务端处理顺序库的-dispatcher-固定执行)） |
| 8 | 控制深度、节点数、数据规模 | 协议限制（[protocol.md 第 9 节](protocol.md#9-限制防止超大或恶意内容)）：块数、单块与整条消息字节数、嵌套深度、节点数、各类型数量上限、事件大小与数量 |
| 9 | 未知组件安全降级 | 降级链 → `fallbackText` → 中性提示；单块失败不影响整条消息 |
| 10 | Markdown-only 模式始终可用 | 消息级 `fallbackText` 必填；`BlockRegistry.markdownOnly()` |

## 3. 动作安全细节

- **声明只来自服务端**：客户端发出的 `type` / `target` 只是回显，以持久化块里的声明为准，不一致即拒绝（`target_mismatch`）。客户端无法凭空构造一个新的动作目标。
- **值只能来自声明**：选项必须是块里列出的 `id`；表单值必须满足字段声明（类型、必填、范围、长度、选项）。自由文本（表单的 `text` / `multiline_text` 字段；已结束消息里的澄清回答作为普通用户消息；开着的中断中三种交互块的 `{freeText}` 作为动作回答）作为**不可信输入**交给宿主，宿主若把它送回模型，必须当作用户输入处理，不能当作指令。
- **一次性、先答者胜**：块状态由 `open` 变为 `resolved` 等之后不再接受动作（`already_resolved`）；可设 `expiresAt`（`expired`）；被新块取代后为 `superseded`。“检查仍为 `open` → 写入结果”必须是一次原子操作，并发的两个答案只有一个成功。拒绝时返回块的当前状态，客户端显示服务端的真实结果。
- **结果不乐观**：客户端在服务端确认之前只显示“提交中”。这样界面上永远不会出现一个“看起来已经选了、其实没有被记录”的答案：一对一时服务端也可能因权限、记录已变化或删除、校验失败而拒绝，同一用户也可能在另一台设备上已经答过；群聊里还可能被别人先答。
- **系统作废留痕**：服务端作废交互块时写 `cancelled` + `reason`，不写 `resolvedBy`，界面上不会把“系统作废”显示成“用户取消”。
- **幂等**：`ActionRequest.id` 是幂等键；同一作用域内同一 ID 的规范化请求必须一致，否则 `invalid_request`；匹配时在当前 `authorize` 通过之后返回第一次的结果，不重复执行。不得在授权前回放已保存结果。网络错误或超时后客户端**复用同一个 ID** 重试（动作可能已执行）；只有服务端明确拒绝、用户重新决定时才换新 ID。宿主需要持久保存结果（保留期不短于客户端离线队列的最长重试期）。
- **破坏性操作**：处理器标记 `destructive()` 时，执行操作时只接受来自 `severity: destructive` 确认块的 `confirm`；中断的 `cancel` / `freeText` 只记录答案、继续运行，不调用破坏性执行处理器。确认块由服务端根据**服务端暂存的待执行操作**生成，确认后执行的就是这份暂存操作，而不是客户端提交的参数。客户端对破坏性确认要求二次点按。
- **权限在宿主**：库不知道“谁能做什么”。`ActionStore::load_block` 必须做作用域校验（这条消息是否属于当前用户可见的范围），`ActionHandler::authorize` 做业务权限检查。推荐对“无权”和“不存在”返回同一个错误码，避免探测。
- **不信任上下文**：`context` 里只有消息 ID 和块 ID；用户身份、租户、权限一律从宿主的会话推导。
- **客户端生成的用户消息 ID 只用于定位和去重**：服务端校验格式、在会话内唯一、属于当前发送者；和别人的消息 ID 撞上时按普通冲突拒绝，不透露那条消息是否存在。助手消息 ID 客户端不能指定。
- **界面不推断权限**：客户端不根据角色之类的信息自己判断“这个人能不能回答”。宿主可以按接收者判断并告诉渲染器某个块对当前查看者只读（[rendering.md 4.2](rendering.md#42-交互块的显示状态)），但这只是展示；真正的检查仍在服务端的 `authorize`。
- **没有动作通道就只读**：库不会把交互退化成“把选项文字作为消息发出去”，避免绕过动作校验。

## 4. 流与事件日志

- **每次连接都鉴权**：包括续传请求；`Last-Event-ID` 只是序号，不是凭据。停止请求和活动消息查询用同一套鉴权；谁能停止由宿主授权。
- **临时进度事件不带数据**：`message.activity` 的 `label` 由宿主写，只描述“在做什么”（如“正在查询…”），不包含查询参数、结果或模型原文。
- **运行步骤只带宿主写的说明**（[protocol.md 4.7](protocol.md#47-运行步骤stepstarted--stepfinished)）：`label` 是宿主为每种工具预先写好的说明，`summary` 由宿主模板生成；**不下发**工具名、调用参数、原始查询结果。持久化的精简记录同样只有标签、最终状态、耗时和可选的一行说明。`summary` 只能包含这位接收者在正文里本来就能看到的信息。
- **中断的回答与其他交互一样受控**（[protocol.md 4.8](protocol.md#48-中断暂停与继续同一条消息)）：回答走动作通道，经 dispatcher 的声明、状态、payload、破坏性确认与宿主权限检查；继续一轮之前在同一个条件写入里确认中断仍开着，重复的动作 ID 不会让运行继续两次。文字回答只是交给 Agent 的一段数据（最长 500 字符），不是指令通道，宿主照常把它当作不可信输入。暂停检查点和消息内容用同样的权限访问。
- **不传模型的思考过程**：模型的推理 / 思考文字不进任何事件、事件日志、快照或持久化消息，也不用来拼 `label` / `summary`。理由：它是未经校验的模型原文，可能复述提示词里的敏感数据，也可能被注入的内容操纵。
- **事件日志含内容**：访问控制与消息本身相同；保留期到期必须删除（默认 `message.end` 或 `message.paused` 后 10 分钟）。默认的进程内缓冲同样按保留期释放，不落盘。
- **响应头**：`Cache-Control: no-store`，防止代理缓存流内容。
- **日志**：库产生的日志只含 ID、类型、序号、耗时、错误码，不含文本与数据内容。

## 5. 模型与适配器

- **数字不由模型编造**：宿主应当让模型通过类型化工具请求数据（“查天气”“查统计”），由宿主执行真实查询后生成块；块的 `metadata.provenance` 记录来源（`tool` / `host` / `model` / `adapter`）。宿主可以制定策略，例如“`provenance = model` 的 `metric` 不允许出现”。
- **适配器不推断事实**：纯文本 Agent 的输出只能变成 `markdown`（`provenance = adapter`）；不从文本里用正则抽取数字生成组件；v1 不支持在文本中嵌入 JSON 代码块来“声明”组件。
- **提示词注入**：即使模型被操纵，它最多能让宿主生成一个合法的、经过校验的块；动作仍受第 3 节约束，危险操作仍需用户在确认块上明确确认。

## 6. 隐私

- 库不联网（除了宿主提供的传输）、不收集遥测；降级与错误统计通过宿主回调交给宿主决定。
- 不加载远程图片，避免追踪像素和 IP 泄露。
- 外部链接打开前显示目标网址。
- 客户端存储由宿主实现，库不额外落盘任何内容。登出或切换用户时宿主调用 `ChatWeaveStore.clear()`，清除聊天缓存、临时状态与续传进度。
- 调试面板只读，导出时默认去掉正文和块数据（[rendering.md 第 8 节](rendering.md#8-调试面板只读)）。
- 运行步骤（[protocol.md 4.7](protocol.md#47-运行步骤stepstarted--stepfinished)）只下发宿主写的标签、状态、耗时和可选的一行说明；工具名、参数、原始结果和模型的思考文字一律不下发。
- **仅群聊：步骤细节按接收者决定**。同一条消息的步骤可能涉及只有部分成员能看的数据（例如“查某位成员的记录”）。步骤细节对谁可见由宿主按接收者决定；要隐藏时**替换**而不是删除（`label` 换成笼统说法、去掉 `summary`），保持事件条数和 `seq` 不变，同步下发的 `steps` 同样处理。库不引入步骤级权限模型，与块级可见性的处理方式一致（见下一条）。
- **仅群聊**：多人共享的会话里，某个块的数据可能只有部分成员能看（一对一会话只有一位用户，不存在这个问题）：当前倾向是由宿主在下发（流、同步）之前过滤或替换成降级文本，库不引入块级权限模型（见 [open-questions.md](open-questions.md) 第 4 条）。

## 7. 宿主检查清单

- [ ] 流端点挂在宿主鉴权之后，续传同样鉴权；无权与不存在返回同一结果。
- [ ] 所有自定义块类型在服务端注册了 Schema。
- [ ] 每个动作处理器实现了 `authorize`，并且有“越权请求被拒”的测试。
- [ ] 破坏性操作走“服务端暂存 → 确认块 → 确认后执行暂存操作”。
- [ ] 动作幂等结果持久保存，保留期覆盖离线重试期。
- [ ] 事件日志有保留期清理任务。
- [ ] 送回模型的自由文本按用户输入处理。
- [ ] 日志不含消息文本与块数据。
- [ ] 每种工具的步骤标签由宿主预先写好；`summary` 用模板生成；没有任何代码路径把工具参数、原始结果或模型的思考文字写进步骤事件。
- [ ] 交互块的“检查 open → 写入结果”是原子的；拒绝时返回块的当前状态。
- [ ] 停止端点与流端点同样鉴权；断线不会被当成停止。
- [ ] 用户消息 ID 在会话内唯一且属于发送者；重复提交按幂等返回同一个助手消息 ID。
- [ ] 登出 / 切换用户时调用 `ChatWeaveStore.clear()`。
- [ ] 调试面板不进入生产构建，或在生产构建中不可打开。
- [ ] 宿主实现通过库提供的一致性套件。
